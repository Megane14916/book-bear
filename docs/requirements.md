# 要件・画面仕様書

> 栞SNS v0.1 / 2026-10-31 / モバイルファースト。`[暫定]` は初期仮決定。

## 1. プロダクトの目的と対象

読書中に気になった位置へ感想を残し、あとから**読んだ流れ（投稿した順番）**に沿って振り返り、他の読者の足跡と交流できるSNS。主要ターゲットはスマートフォンで書籍を読んでいる・記録したい利用者。PCでも閲覧できるレスポンシブWebとして提供する。

**主要な差別化体験**：プロフィール → 本X → Yさんがその本につけた栞の流れ。**ページ順ではなく `created_at ASC, id ASC`** とする。ページが戻る・章を飛ばす・再読しても、記録した順にたどれる。

## 3. 画面とモバイルナビゲーション

### 下部ナビゲーション

5項目を画面下に固定。セーフエリア対応。デスクトップは幅を制限した中央コンテンツかサイドナビに変更してよい。

```text
┌─────────────────────────┐
│ ヘッダー／検索／設定    │
├─────────────────────────┤
│                         │
│   ページ内容            │
│   （縦スクロール）      │
│                         │
├─────────────────────────┤
│ ホーム  検索  ＋  本棚  私│ ← 固定の下部ナビ
└─────────────────────────┘
```

- **ホーム** `/`：全体／フォロー中の切替。投稿カード、いいね、返信数、共有。本文表示モード切替は右上メニュー等。
- **検索** `/search`：本／栞／ユーザーをタブ切替。書籍の候補を選び本棚へ登録。
- **投稿（＋）** `/create`：本を選ぶ（本棚／検索）→ページ（任意）→本文→公開範囲→ネタバレ指定→保存。
- **本棚** `/library`：本人だけに見える登録本一覧、読書状態／進捗編集、栞の流れへ移動。
- **私** `/me`：アカウント・プロフィール編集、自分の本棚への導線、書籍ごとの栞の流れ、表示設定、Google連携。

### 詳細画面（下部ナビは維持または簡略表示）

| 画面 | URL例 | 内容 |
|---|---|---|
| 本の詳細 | `/books/:bookId` | 本情報、登録ボタン、関連する公開栞の導線 |
| 他人のプロフィール | `/users/:userId` | 名前、自己紹介、フォロー、公開栞をつけた本の一覧 |
| **栞の流れ** | `/users/:userId/books/:bookId/bookmarks` | そのユーザーがその本につけた栞を古い順に表示 |
| 投稿詳細 | `/bookmarks/:bookmarkId` | 栞全文、いいね、返信一覧、共有 |
| 栞編集 | `/bookmarks/:bookmarkId/edit` | 本人のみ本文・ページ・公開範囲・ネタバレを変更 |
| 設定 | `/settings` | 本文表示モード、Google連携、アカウント情報 |

### 主要画面仕様

**投稿カード共通**（ホーム・栞の流れ・プロフィール・検索に再利用）：投稿者、書名／書影、ページ番号（設定があれば）、投稿日時、本文（非表示状態あり）、ネタバレラベル、いいね数、返信数、共有、メニュー（本人のみ編集・削除）。栞の流れではユーザー／書籍情報の重複表示を減らせる。

**栞の流れ**：上部にユーザーと本情報。投稿日時の**昇順**、同時刻はID昇順。15件単位で下に追加。ページ番号が戻っても正しい順序。本人には公開・非公開両方、他人には公開のみ。最初の投稿がない場合は空状態を表示。公開栞がない本は他人のプロフィールの本一覧に出さない。

**ホームフィード**：新しい順。既に取得した投稿の下に15件ずつ継ぎ足し、画面遷移はしない。「すべて表示／タップして表示」は**表示だけの設定**で、モード変更でAPIの再取得は不要。[暫定] ネタバレ付き投稿の本文はモードに関係なく初期非表示。

**返信**：元の栞の詳細で表示。元投稿が公開の場合のみ他ユーザーが返信可。返信への返信は作らない。返信にもネタバレON/OFFを設ける。

**本棚**：本棚全体を外部公開する機能は作らない。`user_books` はユーザー専用。他人のプロフィールに表示する書籍は、公開栞が1件以上存在するものを集約して表示する。

### ステータス別UI

- 読み込み中：カード／書影のスケルトン。
- データ0件：説明と次アクション（本を登録／最初の栞を作成／検索）。
- 通信失敗：エラー表示と再試行。
- 匿名ユーザーが公開投稿・いいね・返信・フォローを選択：正式登録の案内。バック側も403。
- ネタバレ指定：本文を隠し「タップして表示」。返信も同様。検索の抜粋や共有文にネタバレ内容を載せない。
- 非公開投稿：本人以外は投稿カードを一切表示しない。直リンクは404（存在情報を隠す）。

## 4. アカウント・認可

| 操作 | 未ログイン | 匿名 | 正式ユーザー |
|---|---|---|---|
| 公開投稿・プロフィールを見る | ○ | ○ | ○ |
| 本棚に登録・進捗編集 | × | ○ | ○ |
| 自分の非公開栞CRUD | × | ○ | ○ |
| 公開栞の作成／非公開→公開 | × | × | ○ |
| いいね／返信／フォロー | × | × | ○ |
| 公開フィードの全体閲覧 | ○ | ○ | ○ |
| フォロー中フィード | × | × | ○ |
| 表示モードの変更 | 端末内 | ○ | ○ |

- 初回の**本棚登録・栞保存**時にセッションがなければ `signInAnonymously()` を呼ぶ。匿名での閲覧では不要。
- 匿名→Google連携はCustom OIDC provider `custom:google` のIdentity連携により同一UIDを維持することが基本フロー。要求scopeは `openid email` のみで、Googleの氏名・画像をアプリのプロフィールへ取り込まない。既存Googleアカウントとの衝突時は**自動統合しない**で案内する（MVP）。設定・実サービス確認の範囲は [認証設計](auth-design.md) と [Google OIDC手順](google-oidc-setup.md) を参照。
- 匿名ユーザーはブラウザデータ消去・別端末で記録を失う可能性があるため、適切なタイミングで正式登録を促す。
- 公開行動の制御はUIだけでなくAPIで必須。

## 5. 投稿と本文表示の仕様

- `bookmarks.visibility` = `public` / `private`。デフォルト `private`（匿名でも安全）。
- `bookmarks.is_spoiler` = true / false。デフォルト false。
- `user_preferences.feed_content_mode` = `all` / `tap`。デフォルト `[暫定] tap`（意図せぬネタバレを減らす）。
- **閲覧ルール**：非公開は第三者に返さない。公開の通常投稿はモード `all` なら表示、`tap` ならタップで表示。`is_spoiler=true` はどちらのモードでも初期非表示。
- ページ番号からネタバレかどうかを自動判定しない。
- APIレスポンスの公開投稿本文は表示モードによらず取得する（タップ時の追加通信を避ける）。ネタバレ指定は秘密保護機能ではない。

## 6. 書籍と栞の位置

- ISBN-13がある書籍はその値を一意に扱う。文庫／単行本のISBNが異なれば別の書籍として管理。
- ISBNを持たない本はタイトル必須で手動作成し `isbn13=NULL` を許可（自動重複排除はしない）。
- 本の総ページ数・栞のページ番号・ユーザーの読書進捗は**別データ**。総ページ数やページ番号はNULL可。
- ページ番号は表示のみ／本の位置の記録。栞の流れの並び順には使わない。
- ISBNカメラ読み取りはP1。P0では文字入力だけでも登録できる。

## 7. 非機能要件

- 画面：モバイルファースト（目安幅360px以上）、片手で下部ナビ操作、タップ領域44px程度を目指す。
- API：初回フィード15件、カーソルページネーション、15件を先に絞りJOIN・集計。栞の流れも同様。
- レスポンス：公開と認可に必要な条件は毎回サーバーで確認。匿名／正式のJWTを検証。
- キャッシュ：TanStack Queryで取得データを保存。ユーザー切替時に私有キャッシュを破棄。サーバー側の権限関連クエリキャッシュは初期無効。
- エラー・状態：ローディング、空、再試行、403、404を定義。
- 画像：書影のみを使い、アップロード画像は初期対象外。外部データの利用規約・書影の配信条件を確認。
- セキュリティ：投稿文字数制限、APIレート制限、XSS安全な描画、所有者判定、非公開情報の漏えい防止。通報・ブロックは公開デモ前の対応範囲を協議。
- アクセシビリティ：画面読み上げラベル、キーボード操作、色だけで状態を表現しない。

## 8. ユーザーストーリー／受け入れテスト

1. 初回訪問者が書籍を選び、ログイン画面なしで非公開栞を保存できる。
2. 匿名ユーザーが公開栞・いいね・返信・フォローを行うと、UIで登録案内が出て、APIでも拒否される。
3. 正式ユーザーが公開栞を作ると全体フィードに新着順で表示される。
4. フィードを下にスクロールすると次の15件が下へ追加される。ページ遷移なし。
5. Yさんプロフィールで本Xを選ぶと、**ページ番号に関係なく投稿した古い順**に公開栞をたどれる。
6. 自分の同じ画面では非公開栞も表示され、他人には表示されない。
7. 表示モード `tap` では通常投稿も隠れ、`all` では通常投稿のみ初期表示、ネタバレ指定は常に初期非表示。
8. ISBNが同じ本を2回追加しても重複しない。ISBNのない本を手動登録できる。
9. 匿名→Google連携で同一ユーザーの本棚・栞が保持される。
10. 公開栞のURLをコピーし、Xのポスト画面を開ける。非公開栞は他人には表示されない。

## 9. 開発前に確認してよい軽微な暫定項目

- タイムラインの初期表示モードは `tap` とするか `all` とするか（本書は `tap` を仮採用）。
- 読書状態の選択肢：`want_to_read / reading / completed` を仮採用。
- 投稿本文最大2,000文字、返信最大1,000文字を仮採用。
- 栞の流れの15件を超える表示は無限スクロールに統一。
- リアルタイム更新、アプリ内リポスト、通知、章単位の位置指定はMVP対象外。
